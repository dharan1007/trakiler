# Contributing to FORM

FORM is an independent research/side project with a public showcase/distribution repository and an intended private core-source boundary.

The most useful public contributions are therefore **evidence, reproducible bug reports, accessibility/UX observations, documentation corrections and carefully scoped feature proposals** rather than unsolicited rewrites of proprietary internals.

## Good contribution paths

1. **Bug reports** — reproduce the issue on the live build and use the Bug Report issue form.
2. **Scientific criticism** — use the Research / Validation Feedback form and cite primary evidence where possible.
3. **Feature proposals** — describe the user problem, expected behavior and data/privacy implications.
4. **Documentation corrections** — identify the exact statement and proposed correction.
5. **Accessibility and browser compatibility** — include browser/device details and reproducible behavior.

## Research standards

When challenging or supporting a training claim, distinguish among:

- direct measurement;
- estimated measurement;
- proxy metric;
- heuristic/rule;
- product ranking;
- gamification score;
- medical/clinical inference.

FORM should not convert a proxy or heuristic into a stronger claim than the evidence supports.

Primary sources such as peer-reviewed papers, DOI records, PubMed entries, standards and official documentation are preferred over unsourced summaries.

## Privacy

Never include:

- passwords or auth tokens;
- service-role or private API keys;
- another person's private information;
- unredacted medical records;
- identity documents;
- precise private training/account exports.

Security vulnerabilities should follow `SECURITY.md` rather than being disclosed in a public issue.

## Pull requests

Small public-surface fixes may be proposed through pull requests. Keep them focused, explain the user/research impact and do not bundle unrelated formatting changes.

Submission of a pull request does not change the repository's current source-rights notice. Do not submit third-party code that you do not have the right to contribute.

## Conduct

Keep discussion evidence-focused and respectful. Disagreement over exercise science, metrics or product design is useful when claims and sources can be inspected.
